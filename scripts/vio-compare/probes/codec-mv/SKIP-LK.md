# H.265 向量推进 + 轻量验证，跳过部分 LK

## 实现和开关

基于已验证的 SG2002 H.265 Normal-P、GOP 60、固定 QP 20 的实际硬件向量缓存。
沿用 [SHALLOW.md](SHALLOW.md) 的完整 FPV 和 TideSense 原始图像及标定、噪声，
保持单目 150 点、FP64 后端、16×15 LK 窗口、原有 RANSAC。没有运行 ROS。

独立实验构建使用 `OPENVINS_CODEC_MV_SKIP_LK=1`，运行选择 `OV_CODEC_MV_LK=verify`。
宏默认不启用，运行默认仍为 `full`；没有接入默认实时 VIO。
`OV_CODEC_MV_MODE=off` 时保留原始 LK 行为。

流程：

1. 使用向量在前一图像的覆盖区域，预测原有特征的新位置；保留原始 ID 与索引。
2. 在前后原图上以双线性插值采样 15×15 范围内的 8×8 网格，共 64 个点。
   使用的是 OpenVINS 原本预处理后的灰度图，编码码流不用于重建图像。
3. 两个窗口都需要足够纹理；比较去均值平均绝对差，以及相对各自均值的 64 bit
   二进制描述子差异。这里没有位置搜索、迭代或亚像素位置修正。
4. 全部通过时直接采用向量预测坐标，跳过 LK，但仍经过原有几何检查、图像边界和 mask 检查。
5. 无向量、边界不满足或验证失败时，采用原始零位移初值运行完整 LK；不让不可信向量约束回退搜索。
6. 每五个原始输入帧强制执行一帧完整 LK，减少连续使用未精细修正的向量。
   这种周期性 LK 不会消除此前已经积累的特征位置误差。

完整图像金字塔和梯度仍照常构建。本轮仅减少一部分点的 LK 计算，没有同时修改深层金字塔构建。
轻量验证通过并不等于有真值证明匹配正确；重投影误差和累计漂移仍需要整段轨迹验证。

| 环境变量 | 严格档 | 较宽松档 `balanced` | 含义 |
|---|---:|---:|---|
| `OV_CODEC_MV_VERIFY_MAE` | 4 | 8 | 去均值平均绝对灰度差上限 |
| `OV_CODEC_MV_VERIFY_HAMMING` | 3 | 6 | 64 bit 描述子允许的不同位数 |
| `OV_CODEC_MV_VERIFY_TEXTURE` | 10 | 10 | 两窗口灰度标准差下限 |
| `OV_CODEC_MV_VERIFY_REFRESH` | 5 | 5 | 强制完整 LK 的输入帧周期；0 表示禁用周期刷新 |

未指定门槛时采用严格档；本轮仅比较这两档，没有使用真值逐点挑选向量或调高测量噪声。

## 本机精度

每组完整回放一次。所有版本完成 FPV 1970 帧、TideSense 885 帧，
初始化后输出状态数分别保持 1782、647，全部状态有限。
关闭实验时，两份录像的全部初始化后时间戳和位姿数值与此前原始基线完全一致，最大差为 0。

| 指标 | 原始 LK | 严格档 | 较宽松档 |
|---|---:|---:|---:|
| FPV 跳过 LK 的输入匹配点比例 | 0 | 10.8% | 26.3% |
| FPV 位置 ATE RMSE，m | 0.2387 | 0.2402 | 0.2374 |
| FPV 首末位置差，m | 1.122 | 0.998 | 1.113 |
| TideSense 跳过 LK 的输入匹配点比例 | 0 | 1.9% | 7.2% |
| TideSense 首末位置差，m | 1.021 | 2.399 | 1.653 |

FPV ATE 使用共同的 816 个真值时间戳、约 30.15 秒，SE(3) 对齐，不拟合尺度，
保留官方相机时间换算。真值未覆盖完整序列，因此这些数字不能证明后半段绝对误差也保持不变。
FPV 较宽松档通过验证的点，有 98.6% 继续通过前端几何检查；这也不能替代真值评价。

TideSense 没有全程外部真值，首末差仅作为返回起点录像的漂移参考。
两档的首末差都变大，不能把 FPV 上的相近 ATE 当成已经验证了自录数据上的通用可靠性。
初始化后 TideSense 跳过率明显低于全段统计：开头静止期间更容易通过验证，因此不能用静止阶段
较高的接受率估算动态 VIO 的收益。

## A53 FPV：1 GHz 实测

原始版和较宽松档各完整运行两次，顺序为原始、实验、实验、原始。
四次均完成 1970 帧、1782 个初始化后状态；各自重复的全部位姿数值完全一致。
两次原始版均与此前 A53 基线的全部位姿完全一致。
以下为每轮初始化之后、略去首次初始化帧的均值，再对两轮均值求平均：

| 指标 | 原始 LK | H.265 向量 + 轻量验证 |
|---|---:|---:|
| 跳过 LK 的点 | 0 | 26.7% |
| 完整 LK 计算，ms | 8.117 | 6.341 |
| 轻量验证及分配回退索引，ms | 0 | 0.277 |
| 匹配阶段合计，ms | 8.123 | 6.639 |
| 原生前端，ms | 25.920 | 24.666 |
| 向量缓存读取及建立索引，ms | 0.003 | 1.129 |
| **前端合计，ms** | **25.922** | **25.794** |
| **相机回调合计，ms** | **50.972** | **50.816** |
| 位置 ATE RMSE，m | 0.2464 | 0.2547 |

验证时间已经包含在匹配阶段和原生前端中，不能再次相加。
完整 LK 计算减少约 21.9%，但前端合计只减少 0.128ms、0.49%；
相机回调合计只减少 0.156ms、0.31%。ATE 比原始版高约 3.4%。
这个量级不足以认为整套 VIO 获得了有意义的加速。

上表尚未计入硬件编码与 MV 提取。沿用之前单独测得的成本作串行估计，前端会成为
`25.794 + 2.934 + 0.557 ≈ 29.285ms`，高于原始版 25.922ms。
实际实时接口可能减少文件读取、重用解析结果或重叠编码，但本轮没有实现这些流水线，
不能据此宣称已经取得端到端加速。

**当前保留为默认关闭的独立实验，不建议接入默认实时 VIO。**
原因是 A53 整体收益很小、实时编码成本尚未覆盖，且 TideSense 自录数据首末偏差变大。

## 计时口径

- 分别记录 64 点验证、完整 LK、归一化、RANSAC、原生前端与完整相机回调耗时。
- `verified_geometry_valid` 统计跳过 LK 的点最终通过几何检查的数量。
- 旧列 `lk_valid` 在新模式里表示交给几何检查的匹配有效掩码，包含直接采用向量的点；
  LK 实际执行点数以 `full_points` 为准，不能把该旧列当作 LK 的执行次数。
- 原生前端不包含回调之前的向量缓存读取和建立索引；比较时将 `mv_prepare_ms` 加回。
- 缓存来自真实硬件编码，但回放时不同时运行编码器。编码和 MV 提取成本不能省略。
  之前 FPV 单独测得送帧到码流约 2.934ms、向量获取解析约 0.557ms；
  两者与回放耗时相加只是串行成本估计，不是已实现的实时重叠流水线。
- 本机首次读图与主机负载会干扰计时；本轮本机时间只作诊断，性能判断使用 A53 对照。

## 复现

```bash
python3 scripts/vio-compare/probes/codec-mv/build.py --skip-lk --caps 1000 \
  --out install/openvins-codec-verify/host
python3 scripts/vio-compare/probes/codec-mv/verify_run.py
python3 scripts/vio-compare/probes/codec-mv/build.py --skip-lk --platform a53 --caps 1000 \
  --out install/openvins-codec-verify/a53
```

本机输入复用 `install/openvins-codec-shallow/{fpv,tide}/vectors.bin` 和 `host-config-*`。
A53 程序部署至 `/mnt/data/openvins-codec-verify/run_record`，复制并执行 `verify_a53.sh`。
它使用之前板上的 `openvins-codec-shallow` 配置、FPV 原始元数据和图片，保留原始时间戳；
不使用已经平移过时间戳的其他 FPV 元数据。

回传 `a53-results/` 后：

```bash
/usr/bin/python3 -S scripts/vio-compare/probes/codec-mv/verify_summary.py
```

所有新构建、原始轨迹、逐帧指标、原生计时、运行日志及 `summary.json`
均放在 `install/openvins-codec-verify/`，不覆盖旧实验。
`summary.json` 为逐次结果，`aggregate.json` 为重复测试汇总及重复轨迹一致性检查。
