## ORB 的 IVE 变体

此前 OpenVINS 的 IVE 候选点路径使用 `STCandiCorner`（Shi–Tomasi），不是硬件 FAST。
本次复用该能力替换 ORB 的 FAST 候选检测，保留原 ORB 后续步骤。
默认质量参数 16。**检测器改变，不保证点集、描述子或检出率与 FAST 相同。**

对录制首张左图重复 10 组，每组两次 detect+compute 和一次 120 点 compute：

| 项目 | 原 FAST | IVE-ST |
| --- | ---: | ---: |
| 总耗时 | 2266.98 ms | 1386.88 ms |
| 检测阶段累计耗时 | 1170.08 ms | 374.24 ms |
| 检出点数 / 次 | 484 | 389 |
| IVE 实际调用数 | 0 | 160 |

组合 ORB 任务减少约 38.8% 耗时。IVE 硬件累计 143.06 ms，
候选点阶段总共 370.78 ms，差额包括拷贝、cache 操作和 CPU 非极大值筛选等。
FAST 路径与未替换 OpenCV 库的检测、映射描述子 checksum 完全一致：
`18026196924591175673` / `167112227764844456`。
IVE 变体 checksum 不同，这是预期的检测器差异。
实际各层调用均通过输出与 scratch 的 DMA 越界哨兵检查。

## 同一段 180 帧回放

输入为 `install/readme-validation-20261019/vio-record`，完整顺序读图；
报告 `completed_processing_fps`，包含输入 I/O、VIO 和后台排空，不包含词袋启动加载。
异步工作线程只有一个待处理槽，调度会改变实际处理的关键帧数量。

| 角点 / 匹配 | FPS | 回环任务数 | 实际 TPU 调用 |
| --- | ---: | ---: | ---: |
| FAST / CPU batch，第 1 组 | 9.193 | 35 | 0 |
| IVE-ST / CPU batch，第 1 组 | 10.269 | 47 | 0 |
| FAST / CPU batch，第 2 组 | 9.451 | 34 | 0 |
| IVE-ST / CPU batch，第 2 组 | 10.065 | 49 | 0 |
| IVE-ST / C906+TPU | 9.963 | 50 | 188 |
| IVE-ST / C906+TPU，额外 CPU 校验 | 10.117 | 49 | 106 |

两组均值从 9.322 到 10.167 FPS，约提升 9.1%；IVE 线程也处理了更多关键帧。
这里的 9.1% 仅是含读图和后台排空的回放吞吐差异，不能表述为纯 VIO 计算加速比。
现有 `profile.csv` 的起止计时在 `imread` 之后，包围 `vio.addImageBundle`。
剔除前 50 帧后，FAST / CPU batch 两轮平均为 112.37 / 108.79 ms/帧，
IVE-ST / CPU batch 为 105.51 / 106.07 ms/帧，IVE-ST / C906+TPU 为 107.38 ms/帧。
这些数值排除了读图，但仅覆盖 VIO 调用，仍受后台回环抢占影响，
不包含调用后的关键帧快照提交或最后排空，不能换算成完整流水线的纯计算 FPS。
要测不含文件 I/O 的完整流水线吞吐，需要另做内存输入基准。
CPU 校验轮的 106 次匹配全部与原 CPU 索引一致。
未校验的组合卸载轮处理 26178 对描述子，TPU 确实执行，但没有额外提高 FPS。
该轮设备处理仅约 11.98 ms，主机提交累计 301.89 ms：小批次搬运、cache 和邮箱开销突出。
所有上述回放均处理 180 帧，tracking 标志均为 180；这不是精度指标。
全部最终确认回环为 0，不能据此评价移动场景的检出率和误检率。
这几轮回放采样 HWM 约 28–29 MiB；该值不能完整代表 ION 占用。

早期 FAST / 原 CPU、FAST / C906+TPU 回放约为 9.29、9.47 FPS；
首次冷回放原 CPU 仅 6.89 FPS，存在明显 I/O 等待，不能挑此值计算加速比。

## 匹配等价与微基准

原匹配的相同词袋节点约束、反向 SVO 匹配、严格阈值和相同距离时的索引顺序均保留。
修复上游输出预分配的上界：应为当前 BoW 点数加过去 SVO 点数。
25 组测试覆盖节点限制、空描述子、并列距离、反向输出数量、跨批归约及阈值 0/1/48/256/257。
CPU batch 和 C906+TPU 均逐索引通过原 CPU 参考比较；后者执行 276 次 TPU 调用。

同一组 272996 对的匹配测试（含主机分组和整理，不含额外 CPU 校验）：

| 路径 | 匹配耗时 | 原 CPU 参考耗时 |
| --- | ---: | ---: |
| CPU batch / NEON | 51.17 ms | 391.59 ms |
| C906+TPU | 112.26 ms | 378.81 ms |

单独 Hamming 探针覆盖全部整数距离 0..256、随机描述子、跨批并列选择和尾批。
100 轮共 204801 对、201 批：CPU batch 27.17 ms，C906+TPU 74.76 ms，
C906 标量 204.68 ms，均通过正确性检查。TPU 不胜过优化后的 A53 NEON。

## 静态实时场景

早期两轮 CPU 与 C906+TPU 都约 19.89 FPS，但各只处理 2 个关键帧任务，
没有匹配、没有 TPU 调用，不能算卸载加速证据。

IVE-ST / CPU batch 的 600 帧实测为 5.354 FPS（去前 50 帧按图像时间约 5.207 FPS），
产生 277 个回环任务，丢弃 78 个回环输入，替换 1633 个相机待处理帧。
IVE 硬件实际调用 4432 次；没有词袋候选匹配和最终回环。
采样 HWM 77304 KiB，最低 MemAvailable 62140 KiB，未触发内存停止条件。
这轮负载明显不同，不能用之前 2 个关键帧的 20 FPS 作公平对照。

随后的当前场景对照：原 FAST / CPU batch 处理了 600 帧，但全部初始化失败，
tracking=0、退出码 1，19.31 FPS **不计作有效 VIO 性能**。
关闭回环的 600 帧为 9.426 FPS，tracking=600；静止时其轨迹仍有严重漂移，
IVE 轮也如此。因此本轮实时运行只记录负载和资源，不能证明稳定 VIO 或精度，
也不能把跨次初始化差异当作 IVE 加速比。
判断检测器性能优先使用上述同录制回放和单图微基准。
