# OV9281 实时双目输入

实时双目＋SC7U22 200Hz 惯性入口另见 [IMU.md](IMU.md)。本文描述纯视觉模式。

本入口将 SG2002 的两路 OV9281 接入 SchurVINS 的双目视觉前端，**不接入 IMU**。
保留原来的离线双目＋IMU CSV 和合成自检。当前支持两路均为 640×400 / 20fps 的 INI。

## 设备运行

```sh
cd /mnt/data/schurvins-gcc11-static
# 真实相机输入冒烟测试，处理 120 对；无需实际标定，不输出位姿文件
./run.sh --camera-smoke /mnt/data/sensor_cfg.ini 120

# 安装镜头并完成标定后，运行纯视觉双目；0 表示持续运行，Ctrl-C 停止
./run.sh --camera actual-calibration.yaml /mnt/data/sensor_cfg.ini /tmp/visual-poses.csv 0
```

`--camera` 必须使用实际的 640×400 双目标定，包含两路 `cameras`、内参/畸变和 `T_B_C`。
此模式不需要 `imu_params` 或 `imu_initialization`，也不会产生 IMU 融合结果。
`--camera-smoke` 使用包内明确标为 `test_only` 的占位几何，只检查真实图像进入视觉前端，
即使日志出现 `tracking` 也不代表定位有效。禁止把该 YAML 用于 `--camera` 输出位姿。
两路顺序为左 0x10 / 2 lane、右 0x60 / 1 lane。

相机模式读取 INI 的两路 `hw_sync`，必须相同：

- `hw_sync=1`：采集进程先准备 PWR_GPIO0/PWM8，再初始化两颗相机，最后启动 20Hz FSIN。
  正常退出、Ctrl-C、客户端断开都会停脉冲并销毁 VI/ISP。
- `hw_sync=0`：自由运行，不操作 PWM。按到达时间近邻配对，不保证曝光同步；正式双目推荐 FSIN。

使用前停止其它相机应用。新采集进程使用 `/run/tidesense-camera.lock`，拒绝多个本程序同时初始化设备。
不要并行运行旧 `capture` 或其它 SDK sample，它们不使用此锁。
没有新增开机服务，也没有修改默认 INI。现有板级 loader 必须已释放显示面板对 PWR_GPIO0 的占用，
参见 `../ov9281/README.md`；当前设备已经完成该配置。

## 输入路径与时间戳

```
OV9281 ×2 → CVITEK VI（每路深度 3）→ schurvins_camera
           → 本地 socketpair → 持续接收线程 → 最新一对（容量 1）
           → SchurVINS addImageBundle → 纯视觉前端
```

- `schurvins_camera` 是 GCC 6 构建的 SDK 采集进程，静态链接 MPI 库、动态链接板上已有的 libc。
  SchurVINS 主程序继续使用 GCC 11 全静态构建，保留现有六项优化开关。
- 将 VI 的 Y 平面按真实 stride 复制为连续的 `CV_8UC1`，复制后立即释放 SDK 帧，
  前端持有独立图像内存。没有图像缩放、磁盘中转或 JPEG/PNG 编解码。
- 带版本头的本地二进制协议传输两路尺寸、帧号、各自 PTS 及两个灰度平面。
  协议仅用于同机小端进程，不是网络协议。接收端检查长度、尺寸、递增序号和时间戳；
  坏头、截断或超时会报错并关闭采集。
- 采集端按 VI 到达 PTS 配对；FSIN 下超过 20ms、自由运行超过 25ms 时，丢弃较早的单帧重新配对。
  不假设“顺序读取的一左一右”天然对应同一次触发。帧号保留为诊断信息。
- 左 VI PTS 从微秒转换为纳秒，作为 bundle 时间；右 PTS 保留在协议头。
  当前内核使用单调时钟，程序也检查其与 `CLOCK_MONOTONIC` 的关系。
  **这是 VI 到达时间，不是 FSIN 边沿或曝光中心时间**；相机—IMU 时间标定尚未做。
- 长闲置后的首帧及 VI/ISP 启动阶段不用于前端；在 VI 开始交付后再丢弃 4 对。
- 接收线程持续读取，前端忙时覆盖尚未处理的旧图像对。统计中的 `replaced_pending` 是主动替换数，
  `max_input_age_ms` 是从左 VI PTS 到前端取出该对的最大时间，不包含本次视觉计算。

上游原实现即使 `use_imu=false` 也会调用惯性后端并断言。补丁
`patches/0006-stereo-visual-only.patch` 让该模式使用已有的 SVO 视觉位姿/结构优化器，
不创建或调用惯性后端；`use_imu=true` 保留原 SchurVINS 路径。

## OV9281 黑白 ISP 配置

`ov9281_isp.h` 在 ISP 初始化和参数加载之后对两路应用专用配置：

- 自动曝光及自动增益；曝光上限 2 ms、亮度补偿 48。
- 手动白平衡 R/Gr/Gb/B 均为 1024（1×），色调增益也为 1×。
- 关闭去马赛克、CCM 和彩色降噪，启用 Mono 输出。
- 关闭前级/后级锐化与 TNR，避免锐化光晕和跨帧滤波影响运动特征。
- 黑电平使用本板遮光 RAW12 实测曲线，按实际模拟增益插值更新（见复测记录）。
- 保留前级 RGB sRGB，关闭后级 Y Gamma 和 DRC，避免重复提亮；保留 Bayer 空间降噪，YNR 强度设为 64。

输出仍为经过 ISP 的 Y 通道，不是传感器 RAW。关闭 TNR 会减少时间上的平滑，
可能让静态噪声更明显；2 ms 上限允许 AE 在暗处延长曝光、降低增益，快速运动时则可能增加模糊。

2026-09-21 诊断发现板端 `cvi_sdr_bin` 是 IMX307 文件，但双目导入返回
`CVI_BIN_SENSORNUM_ERROR`（0xcb000016），在应用前失败，原先实际使用 SDK 默认参数。
不可把复制其他传感器的 tuning bin 当成 OV9281 的校准。

黑白配置上板验证：baseline、mono、mono+sharp、mono+TNR 四组分别取得双路
160 帧，20 Hz。mono 组读回四路白平衡增益均为 1024，Mono 开、Demosaic/CCM/CNR/
PreSharpen/Sharpen/TNR 关，曝光约 1996 µs。重新启用锐化时，颗粒和边缘光晕再次出现。
拍摄过程中场景有人移动，不能从这些截图估算严格降噪比例；也未量化 TNR 运动残影。
截图与日志保存在本机 `install/ov9281-exposure-read/mono-results/`。
后续遮光实测修正了黑电平（见下）；噪声模型尚未标定，这不是最终 tuning。

### 黑电平实测（2026-09-21）

用户完全遮挡两颗镜头，在 640×400/20Hz、2ms 下抓取未压缩 RAW12。
两路分别请求 1×、15.5×模拟增益、1×数字增益采样；每组每路 4 帧。
**后续发现增益索引映射错误，两组当时实际均为 1×，不能作为高模拟增益黑电平验证。**
RAW12 中位数均为 132，均值约 133，1%～99% 分位约 128～140。
将 ISP BLC 从 64 改为 0、128 时，RAW 黑底不变，确认所取 RAW 不受该扣除值影响。
因此应用层配置使用 132，而不是原驱动的 64；没有直接把 RAW10 值乘四猜测单位。
该结果限于本板两颗 OV9281、当前模式和测试温度，不代表跨板/全温标定。
诊断脚本沿用有限 FSIN 帧测试，但 RAW 抓取会消耗额外帧；其结束帧数断言失败
不代表 RAW 抓取失败。最终不抓 RAW 的采集测试另行验证。

遮光端到端对比（AE 开启）：原 BLC=64 时两路输出 Y 均值约 196.8/255，
AE 统计亮度约 49～50、误差约 0，说明黑底偏置被误当成有效亮度。
改为 132 后 Y 均值约 48.0/47.5，AE 统计亮度约 3～4；全遮光导致 AE 将 ISP
数字增益推到约 32×上限，仍有明显噪声，不能把这项测试解读为“噪声消除”。
修正前后均通过双路 160 帧、20Hz 验证。正式程序已部署并恢复 5Hz 标定发布。

### 空间降噪与亮度（2026-09-21）

读回发现默认 YNR 虽开启，但全部 ISO 的 NoiseSuppressStr 都为 0。
现将自动 ISO 表的强度设置为 64，保留原有 coring/滤波参数，TuningMode=YNR_RESULT。
仍不启用 TNR 和锐化。AE u8Compensation 从 56 改为 48，保留自适应目标范围表、
2ms 上限和 BLC=132。未给 ISP 数字增益另外设限，弱光仍可能有较高增益。

同一墙面 ROI（左图 x=110:180,y=140:260）12 帧，去掉帧间整体亮度变化后，
用相邻帧差标准差/sqrt(2)估计时域波动：YNR=0/64/128 分别约 1.90/0.65/0.57
灰度级；ROI 平均亮度约 191.5/190.9/189.1，均无 >=250 的像素。
这是本次场景的估计值，拍摄非严格静态且诊断取帧存在间隔，不能泛化成整机降噪指标。
墙面并非全部数值饱和；大幅降低 AE 参数会造成暗部欠曝，故采用较温和的 48。
截图/连续帧和日志：`install/ov9281-exposure-read/noise-results/`。

### 模拟增益回调修复

随后直接读取 `0x3509` 发现，AE 报告 15.5×时传感器实际仍为 `0x10`（1×）。
`cmos_again_calc_table` 返回表索引，`cmos_gains_update` 却按 Q10 线性值换算，
导致所有档位均钳制为 1×。现通过 Again_table[index] 恢复 Q10 后转 Q4，
并拒绝越界索引。mode_check 覆盖所有表项的完整回调链，上板通过。
此前日志中的“15.5×模拟增益”只是 AE 请求/报告值；高增益黑电平需另行验证。

修复上板后同场景读回：左 `0x3509=0x60`（6×）、右 `0x70`（7×）；
AE 报告与寄存器一致，ISP 数字增益约 1×，曝光保持 1996 µs。
修复后的图像仍有颗粒，未宣称噪声问题完全消除。场景位置发生变化，
未将前后截图用于定量 SNR 比较。实际高模拟增益下的黑电平尚需遮光复测。

### 增益修复后的黑电平复测

2026-09-21 用户完全遮挡双镜头，曝光 1996 µs，传感器/ISP 数字增益均 1×，
ISP BLC 暂设为 0。每档每路 4 帧未压缩 RAW12。增益寄存器与 AE 返回值逐档核验通过。

| --- | --- | --- | --- | --- |
| 1× | 0x10 | 132 | 132 | 3.38 / 3.34 |
| 4× | 0x40 | 148 | 148 | 10.87 / 10.50 |
| 7.75× | 0x7c | 168 | 168 | 19.86 / 19.51 |
| 15.5× | 0xf8 | 180 | 176 | 24.94 / 24.51 |

统计脚本为同级 `dark_stats.py`，统计输出 `stats.json`。

仅当整数偏移改变时写入 ISP。避开首次 AE 尚未就绪的启动阶段。
不按总 ISO 选择偏移，避免数字增益使黑电平档位选错。
曲线仍仅代表本板当前温度/模式，未做全温、全曝光标定；快速 AE 变化时仍可能有帧级生效延迟。

插值端点、越界钳制与全增益范围单调性检查通过。上板曲线烟测时相机辅助进程
实际输出 419 对、20.000fps、配对丢弃 0，但 VIO 前端触发
`frame_handler_base.cpp:1020 Seed-Type not known`，该次完整 VIO 烟测未通过。
相机进程退出后已重新启动原 5Hz 标定模式，确认双路初始化和首对输出正常。

### 两级 Gamma 导致画面发白（2026-09-22）

后续用户仍反馈偏亮和噪声。实测 DRC Enable=0、LocalToneEn=0；
Gamma Enable=1、enCurveType=USER_DEFINE，表在节点 32/128 为 1817/3257，
与 SDK 默认 SDR 曲线一致。读取 `isp_gamma_ctrl.c` 确认：
RGB Gamma 始终开启，初始化为 sRGB；GammaAttr.Enable 控制额外的 Y Gamma。
因此仅把 Y Gamma 换成 sRGB 仍然叠加两次非线性提亮。

正式 profile 现在显式关闭 DRC 和后级 Y Gamma，保留 SDK 前级 RGB sRGB。
AE compensation=48、曝光上限 2ms、动态 BLC、YNR=64 均保持。
不是将整条链路设为线性 RAW 输出。

| Y Gamma 改为 sRGB | 168.12 / 177.76 | 1.396 / 1.238 |
